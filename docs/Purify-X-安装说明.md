# Purify X

适用于 Firefox/Chrome 的 userscript。在 `x.com` 和 `twitter.com` 的推文详情页
过滤垃圾回复，并可选在主要 timeline 中隐藏命中账号名单或高置信推广组合的内容。

当前版本：`2.7.4`

## 安装与更新

1. 在 Firefox 安装 Violentmonkey（推荐）或 Tampermonkey。
2. 在扩展中选择“新建脚本”。
3. 删除模板内容，粘贴 `purify-x.user.js` 的全部代码并保存。
4. 刷新 X 页面。

更新旧版本时直接覆盖原脚本，不要另建一份同时启用。个人名单、关键词和订阅地址
保存在 userscript 管理器的本地存储中，覆盖脚本代码不会清除这些设置。

`2.7.1` 起脚本内置 GitHub 自动更新地址。安装一次后，Violentmonkey/Tampermonkey
会按自身更新周期检查 `main` 分支的 `purify-x.user.js`；只有 `@version` 提升时才会
覆盖更新。更新与下载地址均为：
`https://raw.githubusercontent.com/longmeidao/purify-x/main/purify-x.user.js`。

`2.0.0` 是从旧品牌迁移到 Purify X 的版本。`@namespace`、全部 `xps-*` GM 存储键
和旧公开 API 别名均继续保留；从 `1.14.0` 覆盖升级不会丢失个人名单、订阅或 AI
设置。判定缓存的存储键也不变，但会因脚本版本变化按设计失效并自动重建。

## 日常使用

- 被过滤的回复缩成一行；连续两条以上会合并为一个折叠块。折叠尾行只保留
  1px 可测量占位，不再直接压缩 X 的虚拟 cell，兼顾紧凑显示与滚动稳定性。
- 占位行会写明评分及原因，例如“账号命中本地屏蔽名单”“账号命中 MXGA”
  “命中自定义屏蔽词”或“异常模板”。
- 占位行会按可用宽度自适应：桌面正常宽度下文案在左、按钮在右排成一行；
  图片查看器、分栏或手机竖屏把回复区压窄时，按钮整块换到第二行，再窄则按钮
  之间继续换行。文案始终保持单行，放不下时以省略号收尾，不会被挤成逐字竖排。
- “恢复此条”只恢复当前这条内容；低频的“永久放行”固定在动作区最右侧，会把作者
  加入本地放行名单，此后不再隐藏或标记该账号。
- 账号命中 MXGA 公开名单且设置允许显示时，占位行会出现“向 MXGA 申诉”链接，
  在新标签页打开已填好 handle 的 GitHub 申诉 issue。本地放行只影响自己，申诉
  才可能让维护者
  把误判从公开名单中摘掉；脚本不会自动提交任何内容。可在“Purify X 设置 →
  过滤与显示”关闭该入口。
- 命中账号名单时，账号主页、推文和回复的显示名称右侧会出现独立的
  “低质量账号” badge。badge 与名称横向排列，本身不是链接；旁边的
  “永久放行”按钮可以随时把账号写入本地放行名单，即使该账号因已关注而没有被隐藏。
- 只命中当前回复内容规则、但账号不在名单时，显示“可疑回复”，不会因此把账号
  永久定性。
- 盾牌悬浮按钮显示当前隐藏数量。左键临时显示/重新隐藏全部内容，右键打开设置。
  也可以从 userscript 管理器的脚本菜单打开设置。
- 进入账号的 Media 页面时优先展示 Photos。脚本会展开 Videos 菜单并选择 Photos；
  自动选择只执行一次，之后仍可手动切换 Videos。若 X 未渲染对应控件，脚本保持
  页面原样。
- 按钮避开 X 右下角的 Grok/Chat 悬浮按钮，并按 X 的明暗主题显示。

## 设置面板

设置面板已经接管原 userscript 下拉菜单中的名单更新、同步状态、导入和导出功能；
下拉菜单只保留一个“打开 Purify X 设置”入口。面板包含：

- **公开来源**：以带项目链接的勾选卡片显示。MXGA、Twitter Block Porn 与
  TweetGuard 社区规则默认勾选，可以分别关闭；“保存并更新全部”会立即同步。
- **过滤与显示**：“屏蔽时间线中的可疑账号内容”默认关闭，只处理账号名单；
  “屏蔽时间线中的推广内容”默认开启，处理“Telegram 外链 + 推广话术”，以及
  “限制回复 + 普通外链 + 推广话术”“限制回复 + Telegram 外链”的高置信内容。
  两项彼此独立。MXGA 申诉按钮默认显示，可以单独隐藏。
- **永远放行账号**：每行一个 `@handle`。它的优先级高于本地屏蔽、订阅、
  MXGA、Twitter Block Porn、TweetGuard 和内容规则。
- **本地屏蔽账号**：每行一个 `@handle`，适合只在自己浏览器处理的账号。
- **自定义强屏蔽词**：每行一个规则。中文和完整短语按字面匹配；ASCII 单词按
  token 边界匹配，避免 `art` 命中 `party`；支持精确 `@handle`、`#hashtag`，以及
  `domain:bad.example` 可见域名规则。域名规则只检查页面文字，不解析重定向，也不
  请求外部信誉服务。
- **自定义订阅地址**：每行一个 HTTPS 地址；每 6 小时自动检查一次。
  自定义地址只接受下文的 Purify X JSON v1，不尝试猜测其他项目的 CSV 或私有格式。
- **同步状态**：显示每个内置来源的启用状态、更新时间、错误、去重后的唯一账号数，
  以及两个账号来源之间的重复账号数、社区正文规则数。
- **可选 AI 灰区判断**：默认关闭，可填写 OpenAI 兼容的 Chat Completions
  endpoint、模型 ID、API Key、每日调用上限，并查看或删除 AI 学到的本地规则。

保存和更新时，面板会显示旋转状态；成功后出现绿色确认图标、动效和顶部提示。

本地设置也可以导入、导出为 JSON。随附的
`purify-x-local-list.example.json` 已收录本次人工核实的
`@spam_account_1` 和 `@spam_account_2`（占位示例），可在设置面板中导入；示例账号不再硬编码进
主 userscript。

本地导入文件格式：

```json
{
  "schema": 1,
  "block": ["spam_account_1", "spam_account_2"],
  "allow": ["never_hide_me"],
  "keywords": ["自定义推广词组"],
  "subscriptions": [
    "https://raw.githubusercontent.com/example/repo/main/x-list.json"
  ],
  "builtInSources": [
    "mxga",
    "twitterBlockPorn",
    "tweetGuard"
  ],
  "builtInSourceCatalogVersion": 2
}
```

远程自定义订阅必须是 `schema: 1` 的 Purify X JSON；只读取
`block`、`allow`、`keywords`：

```json
{
  "schema": 1,
  "block": ["spam_handle"],
  "allow": ["false_positive"],
  "keywords": ["高置信度垃圾词组"]
}
```

自定义订阅可以使用任意 HTTPS 地址，因此 userscript 声明了通配
`@connect` 权限；脚本只会请求三个内置来源和你主动填入的 URL，并使用
`anonymous: true`，不向订阅站点发送 X Cookie。订阅更新失败时保留上一次
校验通过的缓存。

### 为什么不使用 `@require` 或 `@resource`

- `GM_getValue` / `GM_setValue` 适合保存用户自己的增删内容，更新脚本时不丢失。
- `GM_xmlhttpRequest` 适合按计划下载并校验 JSON 订阅，也能在失败时保留旧缓存。
- `@resource` 更适合随脚本版本发布的静态资源，不适合用户自行增删、每 6 小时更新。
- `@require` 会把远程内容作为 JavaScript 执行，不应拿来加载可变黑名单数据。

内置的组合规则、混淆归一化和模板算法仍留在主脚本中；可变的账号、字面关键词及
反屏蔽名单则放在本地存储或 JSON 订阅中。

## 内容识别

脚本会识别：

- 昵称中的“同城”“上门”“选妃”及繁体、插空和常见形近写法。
- 回复正文中的“选妃”，以及“同城/上门”与安排、空降、邀约等组合。
- 昵称中的“约萢”等同音混淆，以及“查询附近资源/精准配对/找主人”等推广式
  结构；后者只有与“@提及 + 单个 emoji”低信息回复组合时才达到隐藏阈值。
- 昵称中的“免费、无偿、全国、自取、男士”作为低质量营销先验加分；这些普通词
  不会因为出现在正常回复正文中就直接隐藏。
- “炮友/萢友”昵称，以及“快速匹配通道”等组合话术。
- 多个装饰型昵称在 10 秒内集中发送单 emoji 回复的协调式集群；带正文的批量模板
  现在同样计入该集群检测，不再只看纯 emoji 回复。
- 同一账号在当前回复区重复发送“@提及 + emoji”等低信息内容。
- 同一回复区内多个不同账号复用同一段文本。比对前会去掉链接、@提及、emoji、
  标点和空白，并额外比对一次剥离拉丁字母后的版本，用来识别只换 emoji 或插入
  随机字母的同族模板。较长的 CJK 文本还会用三字片段比较近似度，识别少量增删字
  的变体；倒排索引和 500 条页面记录上限避免退化成全量两两比较。叠词祝福
  （“恭喜恭喜恭喜恭喜”）和短句复读（“确实”）因长度与字符重复度门槛被排除，
  多人讨论同一主题但句式不同也不会被判为模板。
- 正文中间硬插 emoji 打断语句（“我果然太涩了🐨🫡有人想…”）。emoji 跟在标点或
  空格后属于正常用法，不计分。跨账号模板复用和句内 emoji 插入都只是特征分，
  各自都达不到隐藏阈值，必须组合出现才会隐藏。
- emoji 分隔式广告昵称和批量生成型账号 ID；两者只是低权重证据，需与其他特征
  或重复行为组合，不会各自单独隐藏账号。
- `两位数字 + 符号/emoji + 两位数字`（如 `24 🪻 73`）机器回复模板。
- “她太涩了…我真顶不住”“sao货…没人比她sao”“体制内老师sao的很”
  “主页能打✈️”等插入随机字母、替换账号或附加短码的批量模板。
- 站外联系方式、主页引流、短数字/字母 emoji 乱码、秒级时间戳模板等组合。
- `t.me` Telegram 外链与粉丝回馈、福利群、不用付费、今天进群、视频完整版、
  免费开放、进裙入口、唯一链接或“打开即玩”等推广话术的组合。非 Telegram 的
  普通外链仍须同时从 X 结构化数据确认限制回复（如 `by_invitation`）。单独的外链、
  限制回复或推广词不会达到时间线高置信门槛。
- 限制回复与 Telegram 外链同时出现的组合，不再要求额外推广词或暗号。开放回复的
  Telegram 帖仍须命中明确推广话术。

“正常讨论同城配送和上门维修”不会仅因同时出现“同城”“上门”而隐藏。

在推文详情页，主贴始终保留，只过滤下方回复；主贴作者命中账号名单时仍可显示
低质量账号 badge，但不会折叠主贴。Home 的 For You / Following、Explore、搜索、
Lists、书签和通知等 timeline 中，账号名单过滤默认关闭；高置信推广过滤默认开启，
并覆盖账号主页及其 Replies 列表。两项可在“Purify X 设置 → 过滤与显示”分别控制。
单条普通推文碰到关键词仍不会被屏蔽。

## 已关注账号与本地放行保护

过滤前会读取 X 已加载在当前回复卡片中的账号关系状态：

- 当前登录账号自己的内容直接放行。
- 明确为已关注的账号通常放行；只有帖子自身出现“Telegram 外链 + 推广话术”，
  或同时出现“限制回复 + 普通外链 + 推广话术”“限制回复 + Telegram 外链”时才
  进入评分。该例外用于过滤已关注创作者主动发布的福利群、Telegram 和站外产品推广，
  不由账号名单或单个关键词触发。
- 如果暂时无法确认关系，也选择保留，不冒险隐藏。
- 本地“永远放行账号”和订阅 `allow` 均优先于所有屏蔽来源。

关系读取完全在当前 X 页面内完成，不调用 X API，不遍历或上传关注列表。

### 转推

转推在 X 上是一张普通推文卡片，卡片作者是**原推作者**，转推者只出现在顶部的
“XXX 已转推”一行里。因此原作者未关注、又恰好命中名单时，一条你关注的账号转发
的内容会被隐藏。现在会单独识别转推者并按同一套关系规则处理：

- 转推者已关注、是你自己，或在“永远放行账号”里 —— 整条放行。
- 转推者关系暂时读不到 —— 同样放行，与“无法确认关系就不隐藏”保持一致。
  一条转推能出现在你的时间线里，前提本来就是有人转了它。
- 转推者被明确判定为未关注，或在你的本地/订阅屏蔽名单里 —— 回到按原推作者判定。

判定要求同时满足转推文案（中英文及繁体写法）和指向账号主页的链接；置顶、点赞、
“你可能感兴趣”等共用同一个 socialContext 节点的情况不会被误认成转推。取不到
转推者时行为与旧版本完全一致。

放行的转推仍会显示原作者的“低质量账号”badge，内容不隐藏，但来源标记保留。

### 引用推文

引用卡片会同时识别外层作者和被引用作者。被引用作者命中本地、订阅或公开账号名单
时，会作为一条可解释的账号证据参与外层内容判定；占位行会明确写出
“引用作者 @handle 命中 …”。这不会单独绕过外层作者保护：外层作者是当前账号、
永远放行或关注关系暂时未知时，整条仍然放行；已关注作者也只有外层帖子自身命中
上述高置信推广组合时例外。时间线由外层/引用作者账号名单或该高置信推广组合进入
评分；详情页主贴始终保留，只过滤下方回复。

## 自动同步的公开来源

- [Make X Great Again（MXGA）](https://github.com/foru17/make-x-great-again)：
  使用 lite 账号名单、社区规则及误杀白名单。
- [Twitter Block Porn](https://github.com/daymade/Twitter-Block-Porn)：
  使用其公开账号名单。
- [TweetGuard 社区规则](https://github.com/viewer12/tweetguard)：
  使用其公开的 `tweetguard-rules-v1` 正文模板。外部规则只加 5 分，必须与其他
  内容或行为特征组合后才能达到隐藏阈值。

首次运行下载公开名单，以后每 6 小时检查更新；也可以在设置面板中立即
同步并查看状态。外部账号按精确 `@handle` 匹配，不会因显示昵称相似直接命中。
MXGA 白名单会覆盖外部名单和 MXGA 社区规则，但不会关闭你自己的内容规则。

同步时会校验 schema、字段、账号格式、条目数和响应大小；数量异常、格式错误或
网络失败时保留上一次有效缓存。各来源独立更新，一个失败不会清空其他来源。
单条坏数据只丢弃这一条，不再让整份名单作废；只有坏行超过 10% 才判定整份响应
不可信。名单条目上限为 50 万条，超出时截断保留并在同步状态中提示，避免上游
继续增长后整源停更——MXGA 名单在 2026-07-19 至 07-27 之间从 14.7 万条涨到
20.0 万条，约每天新增 6,600 条。

`x.zuoluo.tv` 不可用时，MXGA 账号名单和白名单会退回 GitHub 仓库中每 6 小时
同步一次的 `data/blacklist/v1.json` 与 `data/whitelist/v1.json` 镜像。镜像比
artifact 稍旧且不带分级信息，但可以避免误杀保护随边缘服务一起失效。

### MXGA 条目分级

MXGA 的每条账号带一个 tier 标记：`human` 表示维护者人工确认，`auto` 表示 AI
自动判定。按 2026-07-27 的快照，20.0 万条中人工确认约 3.2 万条（15.9%），
其余 16.8 万条为自动判定；MXGA 官方的 `/v1/check` 接口和 v0.5 扩展内置名单都
只发人工确认部分。因此本脚本：

- 人工确认条目记 8 分，仍可单独达到隐藏阈值。
- AI 自动条目记 6 分，必须再有一条内容或行为特征才会隐藏。
- 同时命中 MXGA 与 Twitter Block Porn 记 10 分。
- 占位行会写明“人工确认”或“AI 自动判定”，以及色情、加密货币、赌博、资源引流、
  营销推广等分类。

设置面板的同步状态会显示两档各自的数量，以及当前名单占条目上限的百分比。

当前只自动同步上述三个公开来源和你自行添加的 JSON 订阅，不代表互联网中的
全部低质量、诈骗或 spam 名单。

内置来源不是按“能找到就添加”选择，而是要求近期仍更新、中文圈实际使用、
公开可审计、可按 `@handle` 匹配且能够匿名稳定下载。按 2026-07-27 的核查：

- MXGA 当天仍有提交，公开名单带治理、审计和白名单。
- Twitter Block Porn 最近一次仓库推送为 2026-06-23，约 2,000 stars，
  且直接提供聚合账号 JSON。
- TweetGuard 在 2026-06 仍有提交，采用 MIT 许可证，并提供专门面向 X 中文
  色情引流和 bot 模板的公开 JSON。项目规模较小，因此规则按低权重使用。
- uBlacklist 本身活跃且流行，但其规则是搜索结果 URL/域名表达式，不是 X 回复、
  昵称或账号名单，不能作为本脚本的关键词订阅直接兼容。
- Botblock 最后推送停在 2018 年，且主要是数字 ID CSV；黄推杀手依赖需登录的
  私有后端；推特鸟盾和 PureTwitter 没有可直接复用的稳定公开名单地址。
  这些都不会出现在可勾选来源中。

不同来源中的重复账号会在同步后合并进一个按规范化 `@handle` 索引的 `Map`。
同一账号只保留一个键，并用来源位标记记录它来自哪些名单；每条推文只做 O(1)
查找，不会随着名单数量或重复数量逐项遍历。原始来源缓存仍分别保留，以便显示来源、
独立失败恢复和下次增量更新。

TweetGuard 与本地/订阅关键词分别用 `Set` 去重；重复字面规则只存一份，不会让
同一个社区来源重复计分。不同证据来源同时命中时仍分别显示，方便判断误封。

## 可选 AI 学习

这部分借鉴 TweetGuard 的分层思路，但默认关闭，也不是“让模型任意改写脚本”：

1. 本地硬规则、名单和已学习规则先运行。
2. 已关注账号、永远放行账号、明显正常内容，以及已经达到 7 分隐藏阈值的内容，
   都不会调用 AI。
3. 只有本地评分为 2–6 分的灰区回复才进入单请求队列；相同账号和内容按指纹去重，
   高置信度正常判断缓存 30 天，垃圾判断缓存 180 天。
4. 只有 AI 明确判为垃圾且置信度至少 90% 才会隐藏。每日默认最多调用 20 次，
   可在设置中调整到 1–200 次。
5. 自动学习只接受回复正文中确实存在的字面片段：中文至少 3 字、ASCII 至少
   5 字符，或至少 3 个 emoji。昵称、账号 ID、过短日常词和模型生成的正则表达式
   都不能写入学习规则。
6. 学到的规则最多 200 条，会在设置面板逐行显示；删除一行并保存即可撤销。
   AI 自动学习规则默认有效 90 天，再次命中会续期；用户在设置面板手动添加的规则
   不自动过期。“清空 AI 判定缓存”不会删除这些规则。
7. 如果某条内容只有依靠 AI 学习规则才达到隐藏阈值，用户连续三次选择“恢复此条”
   或“永远放行账号”，对应自动学习规则会在本地停用。硬编码规则、公开名单和用户
   手动规则不会被这一反馈自动修改。

AI 请求只发送当前灰区回复的正文、显示昵称、账号 ID、本地评分和命中原因，不发送
X Cookie、当前页面 URL、浏览记录或关注列表。API Key 保存在 userscript 管理器的
本地存储中，不会出现在本地名单 JSON 的导出结果；但它不是操作系统钥匙串，能读取
该脚本存储或脚本源码的本地扩展仍属于你的信任边界。

endpoint 必须是 HTTPS 的 OpenAI 兼容 Chat Completions 地址；本机
`http://localhost` / `http://127.0.0.1` 也允许。模型名不硬编码，避免服务商更新后
使用过期 ID。启用前可点击“测试 AI 连接”。任何页面文字都作为不可信数据包进
JSON，系统提示明确禁止把推文内容当作指令，以降低 prompt injection 风险。

这不是无监督“自动进化”：AI 只能新增受上述安全门限制的本地字面规则，不能修改
内置正则、阈值、公开名单、放行名单，也不会自动上传学习结果。这样能提高对新模板
的追踪能力，同时把一次误判扩散成长期误封的风险限制在可见、可删除的范围内。

## 判定缓存与滚动性能

- 公开名单、本地名单、自定义订阅和 AI 学习状态会先从本地缓存读完，再进行首屏
  扫描；联网更新放在首屏处理之后，避免启动时先显示、再隐藏。
- 每条回复按状态 ID、正文、昵称、账号、行为信号和规则版本生成判定键。结果最多
  保存 2,000 条、有效 7 天；X 虚拟列表回收并重新创建同一回复 DOM 时可直接复用。
- 对近期页面已经隐藏过的状态另建最多 2,000 条的内存索引。回复滚出视口后再次挂载
  时，会在 MutationObserver 的同一微任务内恢复隐藏并完成连续分组，不再先显示
  80ms 再重复隐藏。索引键包含详情页或时间线作用域，因此返回原页面时可以复用，
  但不会跨作用域误用；规则或名单变化时仍会失效。
- 脚本版本、阈值、名单、订阅、放行规则或 AI 学习规则变化时，旧判定缓存自动失效。
- 协调式集群和同账号重复回复一旦在当前详情页观察到，不会因为滚动导致相关 DOM
  暂时被 X 回收就变回“未命中”，从而避免同一条回复反复出现和消失。
- 当前详情页最多保留最近 500 条已观察回复的纯数据记录。即使构成模板集群的前一条
  已被 X 从 DOM 回收，后一条加载时仍能与它比较；切换帖子后立即清空，不跨页面追踪。
- MutationObserver 只响应新增/删除的推文、正文、作者和关注状态变化；点赞数、
  图片、视频及其他卡片内部更新不再触发整页评分。

`abs.twimg.com` 是 X 自己的静态资源域名，本脚本不会请求它。若浏览器状态栏长期
停在该域名，通常是 X 正在加载自己的脚本、字体或图片，或网络/拦截扩展使请求迟迟
不结束。1.13.0 起已通过判定缓存和精确 MutationObserver 减少重复扫描；1.13.2
增加虚拟 cell 复用保护。真实 Zen 浏览器 A/B 测试进一步确认，把连续组尾部的
`cellInnerDiv` 强制设成 0 高度会让 X 的滚动坐标与渲染窗口失配。1.13.3 不再修改
虚拟 cell 自身的高度、可见性或 containment，只压缩脚本自己的占位节点并为每条
保留 1px 可测量高度，解决滚动时上下内容消失、整块空白和底部疑似重载的问题。
1.13.4 再加入当前页面的预隐藏缓存，并缩小虚拟单元变动时的 DOM 查询范围，解决

## 向公开项目报告或申诉

脚本不会把本地判定、访问记录或名单自动上传给第三方。自动上传容易泄露浏览行为，
也可能把启发式误判扩散成公开指控。

需要共享时应由用户检查证据后主动提交：

- MXGA 提供人工审核的举报与申诉流程，并发布公开 blacklist/whitelist。占位行的
  “向 MXGA 申诉”只是打开预填好的 GitHub issue 页面，提交与否由你决定。
- Twitter Block Porn 接受 GitHub issue、PR 或维护者使用 X List 的方式贡献账号。
- TweetGuard 的 `community-rules.json` 接受 GitHub PR，可提交人工复核过的稳定
  正文模板。

本地 JSON 的导出结果可以作为整理材料，但不要把私人放行名单、访问记录或未经
人工核实的纯关键词命中直接公开。

## 隐私与权限

- 未启用 AI 时，所有页面内容判断都在浏览器本地完成。
- 脚本只向 `x.zuoluo.tv`、`raw.githubusercontent.com` 下载公开名单或你配置的订阅。
- 启用 AI 后，仅按上一节说明把灰区内容发往你配置的 endpoint；脚本本身仍不上传
  当前页面 URL、浏览记录、X Cookie 或关注列表。
- 不自动举报、拉黑、静音或操作任何账号。
- 详情页主贴始终显示；正文关键词与模板规则只作用于下方回复。

脚本需要：

- `GM_getValue` / `GM_setValue`：保存名单缓存和个人设置。
- `GM_xmlhttpRequest`：下载跨域 JSON 名单。
- `GM_registerMenuCommand`：提供设置和同步入口。

## 调整与调试

全局判定阈值位于脚本开头：

```js
threshold: 7,
```

数值越低越严格，建议在 `6` 到 `10` 之间调整。

在 X 页面开发者工具中可以检查评分：

```js
__PURIFY_X__.scoreReply("回复正文", "显示昵称", "@handle")
```

也可以打开设置或手动同步：

```js
__PURIFY_X__.openSettings()
__PURIFY_X__.localSettings()
await __PURIFY_X__.syncCustomSubscriptions(true)
await __PURIFY_X__.syncRemoteLists(true)
__PURIFY_X__.remoteStatus()
```

旧的 `__X_REPLY_PURIFIER__` 与 `__X_PORN_SPAM_FILTER__` 名称仅作为兼容别名保留。

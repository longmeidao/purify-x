# 架构与构建

Purify X 采用“模块源码、多形态可演进、单文件 userscript 产物”的架构。当前安装入口
仍是 `purify-x.user.js`，但它不是维护入口；项目不把未来形态限定为 userscript。

## 当前结构

```text
src/
├── core/       归一化、关键词匹配、行为信号与评分
├── runtime/    状态、AI、X 页面数据、扫描队列与启动流程
├── sources/    自定义订阅和公开来源同步
├── settings/   本地名单、偏好与设置面板逻辑
├── ui/         占位、账号标记和样式
└── userscript.meta.js
        ↓ scripts/build-userscript.mjs
purify-x.user.js    可安装、可自动更新的单文件产物
```

这些源码片段当前按固定顺序进入同一个闭包，以零运行时依赖保留 GM API、存储键和既有
行为。下一阶段会继续把无 DOM 的纯逻辑提取为可独立导入模块；测试仍直接加载真实发布
产物，防止源码与用户实际安装代码出现两套行为。

## 构建约定

- 只修改 `src/`，不要直接编辑根目录 `purify-x.user.js`。
- `npm run build` 重新生成安装产物。
- `npm run build:check` 只检查产物是否与源码一致，不写文件。
- `npm test` 先执行构建一致性检查，再加载真实产物运行全部回归。
- `npm run check` 同时检查构建一致性和最终单文件语法。

## 外部规则边界

公开来源分别缓存、校验和开关，失败时保留上一份有效数据。BlueNoise 只导入纯文本项，
不执行来源提供的任意正则；命中计 7 分并直接屏蔽，TweetGuard 仍以 5 分参与组合评分，
同一关键词被多个来源命中时不重复叠分。自己、关系未知、永久放行、已关注例外与
MXGA 白名单等保护仍先于评分。

## 形态演进

当前无需仅为拆文件改成浏览器扩展；userscript 仍能覆盖页面内过滤、设置和定时同步。
若后台常驻同步、浏览器工具栏、多页面状态、商店分发或跨设备能力成为核心需求，可在
复用 `core/` 与 `sources/` 的基础上增加扩展入口，而不是重写评分规则。是否增加新形态
由产品能力决定，不设“必须保持单文件项目”的限制。
